The site you are reading. It began as a conventional Next.js portfolio with posts
hardcoded in a TypeScript array, and became a file-based publishing system where a new
article is one `.mdx` file.

## The problem with the original

Every post lived as an object in a 336-line array, its body a trusted HTML string
rendered through `dangerouslySetInnerHTML`. Adding a post meant editing shared source
and writing HTML by hand. Worse, three defects had been live for months without
producing a single error:

- The article container used `prose` classes, but `@tailwindcss/typography` was never
  installed, so headings rendered at 16px and paragraphs had no spacing at all.
- A global `capitalize` on `<body>` was Title-Casing every string on the site,
  including email addresses.
- The chosen typeface was loaded but never applied; the whole site rendered in the
  browser's fallback stack.

None of these threw. The build passed, the types checked, every page returned 200.

## The approach

Content moved out of source and into `content/blog/*.mdx` and
`content/projects/*.mdx`. Frontmatter is parsed with `gray-matter` and validated with
zod, so a malformed date or a missing description stops the build with a message
naming the file and the field, rather than silently emitting broken JSON-LD.

The key constraint was keeping the read **synchronous**. The sitemap, the RSS feed and
`generateStaticParams()` all need the post list at module scope, so frontmatter is read
with `readFileSync` and only the MDX body compiles asynchronously, inside the server
component that renders it.

Syntax highlighting runs at build time through `rehype-pretty-code` and Shiki. Token
colours are inlined into the HTML as CSS custom properties and selected by the dark
class, which gives themed highlighting with no highlighter shipped to the browser.

## What it does

- File-based blog and project content, validated at build time
- Build-time syntax highlighting, heading permalinks, tables of contents, GFM
- RSS feed, per-entry OpenGraph images generated with `next/og`, and a cross-linked
  JSON-LD graph covering Person, Blog, BlogPosting, CreativeWork and BreadcrumbList
- Drafts that stay reachable for preview while absent from every listing, the sitemap
  and the feed, and marked `noindex`
- Per-post language with automatic per-character font fallback, so an article can mix
  Bangla prose with English technical terms without any per-post configuration
- Images referenced by their path under `public/`, measured at build time so none of
  them causes layout shift
